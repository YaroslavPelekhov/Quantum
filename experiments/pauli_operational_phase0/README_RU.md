# Экспериментальный цикл: наблюдаемость квантового нарушения

Серия 720/720 завершена и проверена по всем сохранённым состояниям и
измерениям. Зарегистрированный критерий преимущества **НЕ ПРОЙДЕН**;
см. [итоговый аудит](COMPLETED_AUDIT_RU.md). Ниже сохранён исходный план.

Это переход от поиска общей теоремы к измеримому экспериментальному исходу:
можно ли повысить вероятность обнаружить фиксированное нарушение после шума
при одинаковом бюджете измерений и оптимизации?

## Что запланировано

Протокол зарегистрирован коммитом `3237886` до оптимизации на отложенных
семействах. Шесть систем операторов, три Clifford-представления, пять режимов
шума, восемь повторов: 720 парных условий и 2160 оптимизаций. Два семейства
отложены для проверки переноса. Три метода получают одинаковый максимальный
бюджет: идеальная оптимизация, оптимизация с точной моделью шума, оптимизация
статистического критерия. Все используют одинаковое правило распределения
измерений с доступом к точным средним; это благоприятный oracle-контроль,
а не готовый аппаратный алгоритм.

Лимит запуска — три часа, один вычислительный поток. Для каждого выбранного
состояния независимая реализация квантового канала проверяет результат, затем
256 наборов синтетических измерений оценивают вероятность обнаружения при
10 тысячах, 1 миллионе и 10 миллионах измерений. Сохраняются состояния,
затраты оптимизации, оценки вероятности и интервалы неопределённости.

## Граница новизны

Оптимизировать статистическую значимость вместо величины нарушения — уже
известный принцип: [Jungnitsch et al. (2010)](https://arxiv.org/abs/0912.0645).
Поэтому победа только над идеальным состоянием недостаточна. Требуется
преимущество над сильной оптимизацией с шумом на обоих отложенных семействах;
порог и основания закрытия гипотезы записаны в [PROTOCOL.md](PROTOCOL.md).
Даже положительный исход этой серии — кандидат для следующей проверки,
не подтверждение A*. Пока аппаратных данных, учёта подготовки состояний и
устойчивости к ошибке модели нет. Старые закрытые ветки не возобновляются.

## Воспроизведение

Из корня репозитория, обычным Python с NumPy, SciPy, NetworkX,
threadpoolctl и psutil:

```powershell
python -m unittest discover -s experiments/pauli_operational_phase0 -p test_engine.py -v
python experiments/pauli_operational_phase0/run_campaign.py --seconds 10800 --output results/pauli_operational_phase0/new_campaign
```

Исходники новой серии должны быть закоммичены, папка результата — новой.
Не запускайте другую серию, пока текущая активна. `status.json` содержит PID,
число завершённых условий и причину остановки; `cells/` — завершённые парные
результаты; `REPORT.md` — промежуточные описательные сводки. Неполные средние
нельзя трактовать как итог. Файл `STOP` в папке запуска останавливает работу
на границе условия. Результаты не перезаписываются; автоматического повторного
запуска и восстановления прерванного условия нет.

Контрольный pilot_20260909 проверял только G8 без шума, с меньшим бюджетом:
он воспроизвёл 3.044815 > 3. Это известный положительный контроль, не новая
находка и не часть основной выборки. Перед запуском прошли 12 модульных тестов.

Повторяющийся исследовательский обзор должен сначала проверить активный
процесс и результаты, затем применить зафиксированные критерии опровержения.
Новый цикл регистрируется отдельно, без подгонки этой выборки. Планировщик
зависит от работающего приложения и доступных лимитов; численный процесс
не вызывает модель и не использует QPU или платные облачные API.
